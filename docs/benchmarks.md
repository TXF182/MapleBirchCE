# 面板渲染压测（第 5 节 P0-3）

## 为什么要有这个脚本

工程评判里 P0-3 的核心质疑是：**451 条适配器声明 × 7 个页签 × 13 个模组详情全展开**这一最坏情况，没人量过。
此前所有结论都靠"点一下感觉不卡"，既不能复查，也无法在后续改动中判断是否退化。

脚本：`tests/bench_panel_render.js`（2026-11-09 新增）。

## 口径（必须连这段话一起读，不许外推）

**jsdom 只执行 JS 与 DOM 构建，不跑 CSS 布局、绘制、合成。** 因此本脚本量到的是
**面板逻辑构建耗时**，不等于玩家看到的首帧，也不能用来断言帧率或滚动流畅度。

| 能抓 | 抓不到 |
|---|---|
| 算法复杂度退化（把 O(n) 写成 O(n²)：140 条的平方级渲染约 1~2 s，必撞线） | 真实首帧 / 帧率 |
| 渲染函数里意外的重复遍历、每行重复 querySelector | CSS 布局、层叠、绘制、GPU 合成 |
| 新增页签或折叠组带来的线性膨胀 | 图片解码、字体加载 |
| 页签往返是否有累积漂移（内存里残留节点） | 真机弱机（手机端）表现 |

真机视觉验证仍是独立缺口（P0-2，受 moli SafeMode 阻断，未做），不要用本文数字替代它。

## 数据来源

不是 `tests/data/adapter_matrix.json`（那里只有 `key/varPath/type`，没有面板渲染需要的
`name/note/options`），而是产物里导出的 `setup.mbStageCE.CHEAT_ADAPTERS` —— 真实声明，
与玩家面板看到的是同一份数据。注入后经 `getCheatMods()` 重扫，断言模组数与声明总数都对得上。

## 基线（2026-11-14，Node 22 / jsdom 30 / 段落规模 16,087）

> **口径变更（2026-11-14，四维审查后修正，必读）**：此前 `Story` mock 为 `passages: []`、`size: 0`、
> 无 `lookupWith`，`listAllPassages()` 遍历 **0 段** —— places 页因此只测到 2.1~11.6 ms；
> 而本体 0.5.12.13 真实 16,087 段下 `listPlaceGroups()` 实测 **133~193 ms**，
> 热点在旧基线表上**完全不可见**（不是没压测，是压的数据规模为 0）。
> 现在 mock 注入与本体同规模的 16,087 段，前缀从产物源码的 `indexOf("…") === 0` 形态自动抽取
> （跟随 `PLACE_GROUPS` 实现，不硬编码、不失同步），命中率约 40%。
> 同轮给 `listPlaceGroups()` 加了结果缓存（`07d-places5.js`，三重指纹失效），热态约 6 ms；
> 下表 places 的 127.8 ms 是**缓存未命中的首次**，即玩家打开面板真正付的那一次。

| 项 | 实测 | 阈值 | 余量 |
|---|---|---|---|
| `open()` 首帧（7 pane 建壳 + 默认页） | 5.2 ms | 200 ms | ≈38x |
| 最慢页签 `places`（24 组 × 16,087 段组枚举，缓存未命中） | 127.8 ms | 200 ms | ≈1.6x |
| 次慢页签 `global`（18 组地点 + 原版数值） | 35.5 ms | 200 ms | ≈5.6x |
| 其余页签（char/stage/scenes/mods/yanling） | 16.3 ~ 28.0 ms | 200 ms | ≥7x |
| 最慢单模组详情（归途之书 v1.4.6） | 9.1 ms | 150 ms | ≈16x |
| 13 个详情累计 | 53.8 ms | 1950 ms | — |
| deadwood 全展开（140 行，条目最多） | 61.2 ms | 600 ms | ≈10x |
| 页签往返每轮（4 次切换） | 46.8 ~ 84.8 ms | 400 ms | ≈4.7x |
| 往返极差（漂移） | 38 ms | 200 ms | ≈5x |

阈值取"实测 × 4.7~38"：既不在慢机上假红，又不至于像初版 `3000/2000/1200/5000 ms` 那样
比实测量级宽 70~300 倍、根本拦不住退化。

**本表守不住缓存**：脚本每个页签只切一次，缓存删了 places 仍是 127.8 ms（< 200），不会变红。
守住缓存的是 `tests/places_stage_state.js` 的「组枚举缓存」一节（5 条断言：同段落集返回同一数组引用 /
段落集变化后重算 / 组数恒定 24 / 重算反映新段落集）。

## 断言（17 条）

1. `CHEAT_ADAPTERS` 已导出
2. 重扫后模组数 == 适配器数（13）
3. 面板重扫条目数 == 声明条数（**不写死总数**，加声明不需要改脚本）
4. 声明规模下限 ≥ 400 条（防声明被整体清空后压测空转仍「通过」）
5. 面板根 `#mce-root` 建立
6. `open()` 首帧 ≤ 200 ms
7. 页签数 == 7
8. 最慢页签 ≤ 200 ms
9. 13 个模组卡片全部可点开（缺失 0）
10. 13 个详情累计 ≤ 1950 ms
11. 最慢详情 ≤ 150 ms
12. 能定位条目最多的模组卡片
13. 「全部展开」按钮存在
14. 全展开 ≤ 600 ms
15. 展开后确有行渲染（140 行）
16. 往返每轮 ≤ 400 ms
17. 往返无累积漂移（极差 ≤ 200 ms）

## 复现纪律

- 连跑 3 次 exit 0 才算稳定（单次快机器上的瞬时抖动不足以判绿）。
- 改动 `07a-shell*` / `05a3-modcheat*` / `07d-places*` / `07e-scenes*` 任一面板渲染段后，
  重跑本脚本并与上表逐项对照；某项超基线 3 倍即视为退化，先定位再提交。
